# 멋:테이블 고객 후기

## 현재 상태
2026-09-23: 고객이 승인한 시안은 사진 첨부를 유지하고 Google Drive는 사용하지 않는 방식이다. 상호명(60자)과 직접 입력하는 업종(40자)을 실제 폼·서버 검증·고객/관리자 표시 코드에 반영했다.

운영 main은 405d297f7720bc09139fe161ed220ea812bab3fe이며, 후기 기능은 아직 홈페이지에 연결하지 않았다. reviews-config.js 주소도 비어 있다.

기존 Drive 저장 실패 원인은 Google 계정 전체 용량 15.59GB/15GB 초과로 확인됐다(대부분 Google Photos). 기존 Apps Script 관리자 화면은 로그인 상태에서 정상 접근되며 전체 0건·대기 0건이다.

**배포 차단 사항:** 아래 Code.gs는 기존 Drive 저장 코드이며 신규 저장소로 이전되지 않았다. 고객이 요청한 비-Drive 저장소 연결, 사진 포함 실접수, 관리자 공개·삭제/복원 검증을 끝내기 전에는 이 분기를 main에 병합하거나 운영 URL에 연결하지 않는다. 다음 연결 후보는 비공개 사진 저장을 지원하는 Supabase이며 아직 계정/프로젝트/접근 키를 연결하지 않았다.

검증: 기존 저장 어댑터의 권한·접수·공개·삭제 및 새 상호명/자유 업종 보존 테스트 10개와 프런트엔드 구문 검사 통과. 이 결과는 새 저장소 실서비스 검증이 아니다. Google 편집기/배포본은 이번 수정으로 갱신하지 않았다.

## 기존 Drive 방식 배포 (이전 기록, 신규 배포에 사용 금지)
1. 기존 고객 DB의 소유자 계정으로 새 Apps Script 프로젝트를 생성한다. 기존 lead-db 프로젝트는 수정하지 않는다.
2. Code.gs, App.html, appsscript.json을 업로드한다. 편집기에서 임시 initializeReviews(){setup_();} 함수를 만들어 한 번 실행한 후 반드시 제거한다. 새로운 비공개 Drive 폴더가 생성된다.
3. 고객용 웹 앱: 실행 주체는 소유자, 접근은 모든 사용자. 해당 /exec 주소를 publicUrl에 넣는다.
4. 관리자용 별도 배포: 실행 주체는 접속 사용자, 접근은 본인만. 해당 /exec 주소를 adminUrl에 넣는다. 서버는 REVIEW_OWNER와 실제 로그인 사용자를 매 요청마다 비교한다.
5. 익명 고객의 글·사진 접수, 익명 관리 API 거부, 소유자의 확인 대기 목록, 공개 후 익명 조회, 삭제 후 글·사진 조회 차단을 모두 검증한다. 본인만 배포 옵션과 접속 사용자 옵션이 함께 허용되지 않으면 관리자 배포를 Google 로그인 사용자로 제한하되 서버 소유자 검사 통과를 확인한다.
6. GitHub main의 최신 변경과 합친 다음에만 배포한다. 저장 성공 여부를 확인할 수 없으면 성공 화면을 표시하지 않는다.

## 데이터와 권한
- 상호명, 직접 입력하는 업종(선택), 별점, 후기, 최대 3장 사진, 동의 시각을 저장한다. 전화번호를 수집하지 않는다.
- 이미지 파일은 클라이언트에서 JPEG로 변환해 메타데이터를 제거하고 1MB 미만으로 축소한다. 서버는 크기·MIME·JPEG 시그니처를 재검증한다.
- 모든 원본은 비공개 Drive 폴더에 저장된다. 검토 대기 글과 사진은 관리자만 볼 수 있다. 공개한 글과 사진만 고객용 API가 반환한다.
- 삭제는 해당 후기 폴더(글+사진)를 Drive 휴지통으로 이동한다. 공개 API에서도 즉시 제외한다. 필요 시 소유자가 Drive의 정상 복구 기능을 이용할 수 있다.
- 관리자 작업은 Google 사용자 검증과 서버 발급 세션 토큰을 모두 요구한다. 정적 admin.html은 로그인된 관리 화면으로 이동하는 진입점이며 관리자 비밀번호/토큰을 포함하지 않는다.
- 스팸 방지는 숨김 필드·최대 길이·용량 제한·접수량 제한을 포함한다. 소규모 운영용 Apps Script이므로 트래픽이 커지면 별도 저장 서비스로 이전한다.
- 현재 기존 캡처형 후기 4개는 그대로 유지한다. 새 접수 후기의 공개·삭제 기능과 혼동하지 않는다.

## 검증
`node tests/reviews-backend.test.cjs`는 익명 권한 차단, 대기 사진 비공개, 승인/삭제 상태 전환, 제출 중복 방지와 입력 검증을 검사한다. Google 실서비스 연동 검증을 대체하지 않는다.
