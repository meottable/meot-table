# 멋테이블 월별 장부

운영 경로: `/meot-table/ledger/`

- 기존 연결 코드와 암호화된 `snapshot.enc.json`을 유지한다. 첫 실행 때 기존 내역을 가져온 뒤, 원본 반영본을 열 때와 5분마다 확인해 병합한다.
- 매출·입출금 저장은 AES-GCM 암호화 후 IndexedDB 트랜잭션이 완료되어야 성공으로 표시한다. 오류가 나면 입력창과 기존 저장본을 유지한다.
- 매월 새 기록을 입력할 수 있다. 처음 열면 한국 시간의 이번 달을 보여주며 이전·다음 달과 연도 변경을 지원한다.
- 월 마감은 해당 월의 매출·입출금 사본을 보관하고 다음 달을 연다. 마감된 달의 수정·삭제는 명시적으로 마감을 해제해야 한다. 해제 전 마감본은 월별 history 안에 유지한다.
- 미수금은 선택 월까지 계약한 고객의 **현재 잔액**이다. 지난달 매출에 연결한 이번 달 입금은 이번 달 현금과 현재 미수금에 반영하고, 지난달 마감본은 바꾸지 않는다.
- 이전 자료의 `paid`와 `balance`를 독립적인 기초값으로 보존한다. `amount - paid - balance` 정산 차이도 그대로 유지한다. 이전 입출금은 중복 합산하지 않는다.
- 매출 입력 시 계약금을 함께 저장하거나 별도의 입출금에 매출을 연결한다. 매출번호 중복, 초과입금, 음수/소수 금액과 연결된 입금이 남은 매출 삭제를 막는다.
- 월별 목표는 분리된다. 새 달의 기본 목표는 10,000,000원이며, 이전 달 목표는 기존 자료를 따른다.
- 두 창이 서로의 기록을 덮어쓰지 않도록 저장 버전을 확인한다. 충돌 시 다시 불러와야 한다.

## 저장 범위와 백업

기록은 현재 기기와 브라우저에 저장된다. 원본 매출장부에서 사이트로 들어오는 단방향 동기화를 제공한다. 사이트에서 추가한 내용의 원본 엑셀 역반영, 기기간 로컬 입력 공유, 영업관리 연동은 제공하지 않는다. 홈 화면 앱과 브라우저는 저장 공간이 다를 수 있다.

`전체 백업 받기`는 모든 달의 내역과 마감본을 암호화한 JSON 파일을 만든다. 같은 연결 코드로 복원한다. 전체 복원은 확인 창에서 기록 수와 시점을 보여주며 현재 장부 백업 다운로드를 먼저 요청하고, 유효성 검증 후 한 트랜잭션으로 교체한다. 직전 저장본도 IndexedDB에 암호화하여 보관한다.

`저장한 장부 다시 불러오기`는 이 기기의 저장본을 읽는다. 운영 사이트의 초기 snapshot으로 사용자 편집을 덮어쓰지 않는다.

## 검증

`node tests/model.test.cjs` — 이관·정산 차이, 월/연도 변경, 마감 보호, 이월 미수금 입금, 중복/초과입금, 백업 검증.

`node tests/browser.cjs` — 설치된 Playwright 브라우저가 필요하다. 가상 고객과 임시 키만 사용하고 운영 장부에는 접근하지 않는다.

## 원본 매출장부 동기화

원본 파일은 별도의 비공개 자동화 설정에서 지정한다. 개인정보·연결키·평문 장부는 저장소에 넣지 않는다. 원본 변경 확인 자동화가 매시간 Library 최신 버전을 확인하고 변경이 있으면 `tools/build_source_snapshot.py`로 검증 및 AES-GCM 암호화한 `snapshot.enc.json`과 비식별 `source-status.json`만 같은 커밋에 게시한다. 기존 원본 연결 코드를 사용하고 원본 파일을 수정하지 않는다.

변환기는 `주문관리`와 `매출입력`의 계약금액·누적입금·미수금을 대조하고 계약금+잔금+정산차감으로 재계산하여 일치해야 게시한다. 실제 입출금은 `모바일입력`을 사용한다. 최신 파일을 못 읽거나 합계가 다르면 게시하지 않는다.

사이트는 연결 후·다시 열기·5분 간격·`원본 반영본 가져오기`로 게시된 자료를 확인한다. 원본 파일의 즉시 읽기 버튼이 아니며 매시간 확인 및 배포 시간만큼 지연된다. 입력창이 열렸거나 편집 중이면 자동 반영을 미룬다.

`source-sync.js`는 기존 반영본, 최신 원본, 기기 기록을 비교한다. 원본의 입금 완료·새 거래·삭제를 가져오고 별도 기기 입력은 보존한다. 같은 거래의 원본 정산과 기기 입금이 함께 바뀌거나 양쪽에서 같은 필드를 다르게 수정하면 전체 동기화를 보류하고 사용자에게 표시한다. 미수금을 임의로 덮어쓰거나 입금을 이중 합산하지 않는다. 마감 당시 사본은 보존하고 현재 미수금만 최신 원본을 따른다.

`node --test tests/source-sync.test.cjs` — 최초 이관, 재실행 중복 방지, 로컬 추가 보존, 충돌·중복 입금 보류, 원본 삭제·마감 보존 검증.
