# 사장님 문의 문자 알림 — 연결 준비본

아직 운영 활성화하지 않았습니다. 고객 화면·기존 접수·후기·카카오 직통 연결은 변경하지 않습니다. 문자 계정 설정과 **실제 접수 Apps Script의 최신 서버 코드**가 있어야 연결을 마칠 수 있습니다. 저장소의 `backend/Code.gs`는 후기 서버이며 접수 서버가 아닙니다. 이 파일로 덮어쓰면 안 됩니다.

## 현재 확인한 구조

- `lead-db.js`는 기존 Apps Script에 no-cors POST하고 `unconfirmed`를 반환합니다. 이 응답만으로 저장 성공 또는 문자 발송을 판단하지 않습니다.
- `admin.html`은 비공개 고객 DB 바로가기를 제공합니다. 현재 문의가 영업콘솔 고객 목록에 자동 동기화된다고 표시하지 않습니다.
- 이 모듈은 **저장된 문의의 고유 접수번호를 DB에서 다시 읽어 확인한 뒤** 대기열에 추가합니다. 페이지 조회·상담 버튼 클릭·카카오 대화·전화 통화 자체에는 발송하지 않습니다.
- 공개 함수/HTTP 엔드포인트가 없습니다. 모든 함수는 `_` 접미사로 클라이언트 RPC에서 차단됩니다. 기존 서버 저장 코드가 호출하는 모듈입니다.

## 연결 절차

1. SOLAPI 계정 인증, 발신번호 등록, 잔액 준비. 수신할 사장님 번호를 별도로 확인합니다. 비밀번호·API 비밀키를 채팅이나 GitHub에 쓰지 않습니다.
2. 기존 문의 접수 Apps Script의 최신 코드를 백업·검토합니다. 문의별 고유 접수ID와 실제 저장 탭/열을 확인합니다. 고객ID를 사용하면 같은 고객의 재문의 알림이 누락되므로 금지합니다.
3. `OwnerSms.gs`를 해당 **문의 접수 프로젝트에 추가**합니다. Script Properties에 다음을 직접 설정합니다.
   - `SMS_DB_ID`: 실제 문의 저장 스프레드시트ID
   - `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`: 서버 전용
   - `SMS_FROM`: 등록 완료한 발신번호(숫자)
   - `SMS_OWNER_TO`: 확인한 사장님 휴대폰 번호(숫자)
   - `SMS_ENABLED`: 초기 `false`
   - `SMS_DAILY_LIMIT`: 기본 20회, 일일 발송 시도 상한. 한도 초과 문의는 다음 날까지 대기합니다.
4. 편집기에서 `meotSmsSetup_` 실행. 별도 `_문자알림` 탭만 생성합니다. 고객 원본 열은 바꾸지 않습니다.
5. 기존 접수 저장 성공 후, 기존 저장 잠금을 해제한 지점에서 `meotSmsEnqueueStored_(실제탭명, 저장행, 접수ID열, 고유접수ID)` 호출합니다. 실패를 문의 저장 실패로 반환하지 말고 별도 운영 오류로 기록합니다. 저장과 대기열 등록 사이 실행 중단에 대비해 실제 스키마 기준 누락 접수 재대조를 구현·검증해야 합니다. 이 부분은 접수 서버 원본을 확인하기 전 임의로 연결하지 않았습니다.
6. 승인된 테스트 문의 1건으로 저장→대기열→사장님 실제 수신을 확인합니다. 발송 테스트 시에만 `SMS_ENABLED=true` 후 `meotSmsProcess_`를 수동 실행합니다. 정상 수신 확인 후 `meotSmsInstallTrigger_` 실행으로 약 1분 간격 처리합니다. Google 실행 사정에 따라 지연될 수 있어 즉시 수신을 보장하지 않습니다.
7. 홈페이지 접수 성공 표시와 영업콘솔 자동 목록 연동은 별도 미완료입니다. 기존 no-cors 응답을 성공으로 바꾸지 않습니다. 확인 응답 API와 관리자 인증을 설계한 뒤 활성화합니다.

## 상태 및 운영

`queued` 대기 / `sending` 요청 중 / `accepted` 공급자 접수 / `rejected` 요청 거절 / `unknown` 결과 불명.
`accepted`는 실제 휴대폰 수신 성공이 아닙니다. 공급자 발송내역과 테스트 휴대폰에서 최종 수신 확인이 필요합니다.
통신 실패·실행 중단은 자동 재전송하지 않습니다. 공급자 내역과 대조해 미발송이 확실한 건만 관리자가 `queued`로 돌려 재시도합니다. 수신 실패도 공급자 내역에서 확인해야 하며 자동 상태 조회/웹훅은 이 준비본에 포함되지 않습니다.
중지는 Script Properties `SMS_ENABLED=false`. 기존 대기열을 지우지 않습니다. 초기 준비 중 모인 오래된 테스트 문의는 활성화 전에 검토하고 필요하면 상태를 `cancelled`로 변경합니다.
문구는 접수ID와 영업콘솔 링크만 포함하며 고객 전화번호·본문을 보내지 않습니다. 링크 포함 길이 때문에 **LMS(장문 문자)**로 발송되며 공급자 요금이 적용됩니다. API 거절/불명 결과를 포함한 시도도 안전상 일일 한도에 포함합니다.
